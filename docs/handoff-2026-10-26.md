## Состояние Шага 1: код готов, сборка зелёная, финальная проверка в браузере НЕ завершена

Сделано (компилируется, `npm run build` проходит):

- **BoardNodes.tsx**: `Handles` рендерит на каждую сторону видимый source-хендл с кружком `.handle-dot` и невидимый target-хендл точно под ним (классы `handle-source`/`handle-target`; id одинаковые). Старые связи с `targetHandle` работают; `ConnectionMode.Loose` разрешает тянуть/принимать из любой точки. Хитбокс 20px (`hitboxStyle`), `INWARD`/`dotClass` удалены.
- **index.css (блок ~300–370)**: хитбоксы всегда активны (`pointer-events` не трогаем), невидимость чисто визуальная (opacity 0 → 1 по `.react-flow__node:hover` или `.connections-active`), масштабируется только кружок (`scale .5→1`), ховер точки и состояния `connectingfrom/connectingto/valid` красят кружок в `var(--color-accent)`.
- **BoardView.tsx**: БЛОК «связь в два клика» — состояние `dragConnecting` (drag-связь) + `clickConnecting` (клик-режим) из пропсов `onConnectStart/onConnectEnd` и `onClickConnectStart/onClickConnectEnd`; `cancelClickConnect()` сбрасывает **внутреннее** `store.setState({ connectionClickStartHandle: null })` (RF сам НЕ отменяет режим по Esc/клику по холсту — добавлены Esc-эффект и `onPaneClick={cancelClickConnect}`); подсказка «Кликните по точке другой карточки…» при `clickConnecting`; класс `connections-active` на обёртке холста. `connectNodes` — единая точка создания связи (петли/дубли отсекаются), используется `onConnect`.

### Ключевые открытия сессии (не переоткрывать)

1. **RF v12.12 умеет нативную связь в два клика** (`connectOnClick` по умолчанию): клик по точке → клик по точке другой карточки = связь (проверено в браузере, edge создаётся). Свой pending-механизм НЕ нужен и конфликтовал.
2. **«Не с первого раза кликается»** — корень был: (а) хитбоксы были `pointer-events:none` до `:hover`; (б) `scale(0.5)` на хендле сжимал хитбокс вдвое и плавал от hover-таймингов. Лечение: хитбокс всегда активен, масштабируется только кружок.
3. **d3-drag узла вызывает `stopImmediatePropagation` на mousedown** при клике по телу карточки — события до React не доходят (React слушает на корне). На хендлах класс `nodrag` спасает, mousedown всплывает.
4. **Ctrl+Z «при рисовании» и Ctrl+K не работают на русской раскладке**: `BoardView.tsx:551` и `SearchPalette.tsx:22` сравнивают `event.key==='z'/'k'`, на ЙЦУКЕН приходит `'я'`/`'л'`. Фикс Шага 2.1: `event.code === 'KeyZ'/'KeyK'`.
5. **Гипотеза случайного z-порядка карточек** (жалоба «некоторые блоки получают приоритет»): `listNodes` возвращает строки в порядке случайных UUID, `mergeNodes` пересобирает массив в этом порядке после каждой записи, а RF рисует «кто позже в массиве — тот выше». Фикс Шага 2.2: сохранять прежний порядок в `mergeNodes`, новые дописывать в конец.
6. **Инвариант handleBounds** (см. docs/release-notes-0.2.1.md): синхронный замер BoardView.tsx:398–425, `useMeasureNode`, предзаданный `measured` в `toFlowNode`. При изменении точек НЕ удалять эти механизмы.
7. В IAB-панели ZCode локаторные клики зависают: работать через `evaluate` (координаты) + `tab.cua.click/drag/move`. d3-drag съедает mousedown на телах карточек — это нормально.
