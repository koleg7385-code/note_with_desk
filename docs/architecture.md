# Архитектура: локальное приложение «заметки + доска»

Local-first, без бэкенда, без авторизации. Всё состояние живёт в браузерной базе,
а в десктопной сборке — в папке `data` рядом с приложением.

---

## 1. Стек

| Слой | Выбор | Зачем именно это |
|---|---|---|
| Язык / сборка | TypeScript (strict) + Vite | мгновенный HMR, ноль серверной логики |
| UI | React 19 | вся нужная экосистема (редактор, канвас, поповеры) — React-first |
| Стили | Tailwind CSS v4 + `@tailwindcss/vite` | токены темы в `@theme`; классы работают и в узлах канваса, и в блоках редактора |
| Редактор | Tiptap 3 (ProseMirror) | документ = наша схема: таблицы, чек-листы, картинки как наши узлы |
| Канвас | React Flow `@xyflow/react` 12 | узел = React-компонент, внутри живёт превью заметки; зум, связи, миникарта из коробки |
| Хранилище | IndexedDB через Dexie 4 | транзакции, индексы, реактивные `liveQuery`, версии схемы, Blob для картинок |
| Поиск | MiniSearch | полнотекст по заголовкам и тексту, префиксы и опечатки |
| Поповеры | Radix Popover | портал (не обрезается контейнерами), закрытие по Esc и клику вне |
| Панели | `react-resizable-panels` 4 | сайдбар + рабочая область, сворачивание |
| Десктоп | Electron 45 + electron-builder | portable `.exe`, системные диалоги файлов, данные рядом с приложением |

### Почему они «дружат»

- **React везде.** Узлы доски, блоки редактора, поповеры, панели — один рендер-механизм.
- **Одна система стилей.** Tailwind и CSS-переменные одинаково работают в сайдбаре, внутри документа и на канвасе.
- **Нет сетевого слоя → нет слоя кэша.** Нет TanStack Query и нормализации ответов сервера: данные идут из базы прямо в компонент через `useLiveQuery`.
- **Разделение «быстрое vs долговечное».** IndexedDB хранит смысл, локальное состояние — то, что умирает вместе с окном, во время набора текст принадлежит редактору. У каждого состояния ровно один владелец.
- **Тяжёлое грузится по требованию.** Редактор и канвас вынесены в отдельные чанки через `React.lazy`.

Правила, которые держат структуру живой:

1. Компонент никогда не обращается к Dexie напрямую — только через функции из `db/repo.ts`.
2. Формат данных описывается простыми TypeScript-интерфейсами в `db/db.ts`.
3. `db/` не знает про UI; `lib/` знает про `db`, но не про компоненты.
4. Новый файл появляется, когда в нём есть отдельная ответственность.

## 3. Модель данных

Ключевая идея: **`pages` — источник правды, доска — проекция с координатами.** Узел доски не копирует текст заметки, а ссылается на неё; картинка не лежит в документе, а ссылается на запись в `assets`.

### Таблицы (Dexie, версия 2)

**`pages`** — страницы (заметки и базы данных)
`id, title, icon, text (плоская проекция), doc (дерево Tiptap), parentId, kind ('note'|'database'|'daily'), tags[], archived (0|1), favorite (0|1), wide (0|1), cover ('g1'…'g6' | 'a:<assetId>' | null), db (DatabaseDoc | null), createdAt, updatedAt`

**`boards`** — холсты
`id, title, icon, description, parentId, favorite (0|1), viewport, drawing (Stroke[]), createdAt, updatedAt`

**`nodes`** — элементы доски
`id, boardId, kind ('page'|'sticky'|'text'|'image'|'group'), refPageId, refAssetId, x, y, w, h, color, data {text?, caption?}, createdAt, updatedAt`

**`edges`** — стрелки
`id, boardId, sourceId, targetId, sourceHandle, targetHandle, label, color, dashed (0|1), isVisual, hidden, createdAt`

**`assets`** — картинки
`id, name, mime, size, blob, createdAt`

**`links`** — смысловые связи (пока не заполняется, шаг 13)
`id, fromType, fromId, toType, toId, kind, origin, createdAt`

Правила про схему:

- Флаги хранятся числами `0|1`: IndexedDB не умеет индексировать boolean.
- Поля без индексов (`icon`, `doc`, `refAssetId`, `sourceHandle`, `favorite`, `wide`, `cover`, `db`, `drawing`, `color`, `dashed`) не требуют новой версии: у старых записей их просто нет, а интерфейс подставляет значения по умолчанию. Версия поднимается только при добавлении хранилища или индекса — так появилась версия 2 с `assets`.

### Дерево страниц

`pages.parentId` и `boards.parentId` указывают на **любой** объект: родителем может быть и заметка, и доска. Единой таблицы «дерево» нет — `listTree()` в `repo.ts` собирает страницы и доски в плоскую ленту `TreeItem`, а сайдбар строит из неё ветки. Объект считается корневым, если `parentId` пуст или родитель не найден (например, его удалили).

- `archiveItemTree` обходит поддерево и архивирует страницы/удаляет доски, чтобы не оставалось сирот.
- `duplicatePage` клонирует `doc` и `db`; `duplicateBoard` копирует доску, узлы и стрелки с переназначением id.
- `getTrail` поднимается по родителям и отдаёт хлебные крошки; цикл ограничен 32 шагами и множеством посещённых.
- Избранное — флаг на самой записи; библиотека просто фильтрует `listTree()`.

### База данных (DatabaseDoc)

`kind: 'database'` превращает страницу в таблицу. Документ:

```
DatabaseDoc = {
  view: 'table' | 'gallery' | 'calendar',
  columns: { id, name, type: 'text'|'number'|'status'|'date'|'checkbox', options? }[],
  rows: { id, cells: Record<columnId, string|number|boolean|null>, createdAt }[],
}
```

Все три вида читают один документ, поэтому переключение вида ничего не теряет. Статус-колонка хранит варианты в `options`; цвет читается по смыслу значения («Готово» зелёный, «В работе» синий, «Не начато» серый), а не только по порядку. Календарь берёт первую колонку типа `date`; если её нет, предлагает добавить.

Шаблоны (`DATABASE_TEMPLATES` в `db/database.ts`) — это функции, возвращающие готовый `DatabaseDoc`. Модалка показывает превью, созданное из обычных div'ов, поэтому карточки не зависят от картинок.

### Как связаны заметки, доска и картинки

1. **Узел-зеркало** (`kind: 'page'` + `refPageId`) показывает заголовок и первые строки заметки; текст живёт только в `pages`. Двойной клик открывает заметку.
2. **Стикер** хранит текст у себя в `data.text`.
3. **Текст без рамки** (`kind: 'text'`) — тот же `data.text`, но узел рисуется без карточки: подпись прямо на холсте.
4. **Узел-фото** (`kind: 'image'` + `refAssetId`) ссылается на запись в `assets`, подпись — в `data.caption`, ширина — в `w` (ручка меняет её с учётом зума холста).
5. **Картинка в заметке** — атомарный узел `image` с `assetId`. В документе нет base64: иначе каждое сохранение перезаписывало бы картинки вместе с текстом.
6. **Свободное рисование** живёт не в узле, а в `boards.drawing`: штрихи — это `{ color, width, points: [x0,y0,x1,y1,…] }` в координатах холста. Слой `<svg>` с той же трансформацией (`viewport.x/y/zoom`), что у React Flow, рисует их поверх узлов; пока включён маркер/ластик, второй прозрачный слой перехватывает мышь. В базу штрих попадает один раз — на `pointerup`.
7. **Обрезка фото** не меняет исходник: `CropModal` рисует выделение на canvas, получает Blob, кладёт его новым `asset` и возвращает новый id. Документ/узел просто начинает ссылаться на новую запись.
8. **Связи.** `edges` — отрисовка, `links` — смысл (обратные ссылки, граф). Нарисованная «для разглядывания» стрелка отличается флагом `isVisual`. Цвет и пунктир — поля самой стрелки; мини-тулбар появляется у середины SVG-пути и живёт в координатах холста.

### Три уровня состояния

1. **IndexedDB** — долговечное: тексты, документ, состав узлов и связей, координаты после жеста.
2. **Локальное состояние экрана** — эфемерное: активный экран (в `localStorage`), позиции узлов во время перетаскивания (внутри React Flow), ширина узла-фото во время растягивания.
3. **Локальная копия полей** — пока идёт набор, значения живут в `useAutosave` или в состоянии узла: запись с дебаунсом и принудительный flush при уходе со страницы, размонтировании и `visibilitychange`.

### Инварианты

- Сид создаётся событием Dexie `populate` — один раз при создании базы.
- `navigator.storage.persist()` при старте.
- Ссылка на удалённый объект в `localStorage` не роняет экран: показывается «Объект не найден».
- Удаление узла уносит его стрелки, удаление доски — её узлы и связи; удаление страницы/доски уносит всё поддерево.
- Редактор не пересчитывает высоту заголовка по `scrollHeight` один раз: панель на первом кадре бывает нулевой ширины, поэтому `GrowTextarea` слушает `ResizeObserver` и пересчитывает высоту при смене ширины.
- У всех узлов React Flow сразу заполнен `measured`: без него `nodesInitialized` остаётся `false`, и библиотека не рисует **ни одной** связи, пока новый узел не будет измерен.
- Падение панели перехватывает `ErrorBoundary`: пользователь видит сообщение и кнопку перезагрузки, а не пустое окно.
- Undo не делаем сквозным: история Tiptap внутри текста, стек обратных команд для доски.
- Бэкап — экспорт и импорт JSON. Local-first без бэкапа = потеря данных.

## 4. Десктопная сборка

- **Данные строго в папке установленной программы.** В главном процессе до создания окна:
  `installDir = app.isPackaged ? dirname(app.getPath('exe')) : корень проекта`, `dataPath = join(installDir, 'data')`, затем `app.setPath('userData' | 'sessionData', dataPath)`. Установщик новой версии кладёт файлы в ту же папку и не трогает `data/`, поэтому обновление поверх старой версии сохраняет заметки.
- **Установщик NSIS.** `directories.output: "releases/v${version}"` — каждый билд лежит в папке своей версии. `oneClick: false`, `allowToChangeInstallationDirectory: true`, `deleteAppDataOnUninstall: false`. `data/` к удалению приложения не относится и остаётся на месте.
- **Иконка.** `scripts/make-icon.mjs` рисует тёмную плитку с открытой книгой и закладкой, кодирует PNG через `zlib` и собирает многоразмерный `build/icon.ico`. Иконка указана в `BrowserWindow` и в `win.icon` electron-builder; `build/icon.*` попадает в пакет через `files`.
- **Своя схема `app://` вместо `file://`**: у страницы появляется настоящий origin, иначе движок отказывает IndexedDB. Обработчик отдаёт файлы из `dist` через `net.fetch`.
- **Экспорт и импорт** идут через системные диалоги (`ipcMain.handle` + `contextBridge` в `preload.cjs`), поэтому файл не оказывается самопроизвольно в «Загрузках». В браузере тот же код работает через скачивание и выбор файла.
- **Скрипты:** `npm run app:dev` (Vite + окно Electron), `npm run app:icon` (перегенерировать иконку), `npm run app:build` (NSIS-установщик в `releases/v<версия>/`).
- **Служебные флаги:** `NWD_PROD=1` — загрузить собранную версию без упаковки, `NWD_SMOKE=1` — безоконная самопроверка (окно скрыто, в лог печатается путь данных и список баз, процесс завершается).
- Папки `data/`, `dist/`, `release/`, `releases/` исключены из наблюдения Vite: файлы профиля Chromium заняты процессом, и наблюдатель сыплет `EBUSY`.

## 5. Заметки по API (стоили времени, пусть не стоят повторно)

**`react-resizable-panels` 4** — API отличается от v3 из большинства примеров: `Group` (не `PanelGroup`) с пропом `orientation`, `Separator` (не `PanelResizeHandle`), ссылка передаётся пропом `panelRef`, хук — `usePanelRef()`. Числовые размеры трактуются как пиксели. `overflow` вложенного div задаётся только через `style`. Отдельного колбэка сворачивания нет: состояние берём из `onResize(size => size.inPixels === 0)` и сразу выставляем при imperative-вызове.

**`useLiveQuery`** отдаёт `undefined`, пока запрос не вернулся. Третий аргумент (`null`) отличает «ещё гружу» от «не найдено». Внешняя запись в IndexedDB (не через Dexie) не будит подписчиков — после импорта или ручной правки базы нужна перезагрузка страницы.

**Tiptap 3** — `StarterKit` уже включает `underline`, `link` и `codeBlock`. `Color` и `FontSize` живут в `@tiptap/extension-text-style`, `TextStyle` регистрируется отдельно. Таблицы — `TableKit` из `@tiptap/extension-table`. `BubbleMenu` импортируется из `@tiptap/react/menus`. Состояние панели — через `useEditorState`. **Вставку из буфера делать через `editorProps.handlePaste`, а не через подписку на DOM-событие:** `editor.view` до монтирования выбрасывает «The editor view is not available», и без границы ошибок это гасит всё приложение.

**React Flow 12** — `colorMode="dark"`, `connectionMode={ConnectionMode.Loose}` (тянуть от любой точки к любой), `zoomOnDoubleClick={false}` когда у узла есть своё действие на двойной клик. Событие перетаскивания типизируется как `OnNodeDrag<NodeType>`. Внутри узла поля ввода помечаются `nodrag` и `nowheel`. **Узел, добавленный после первого рендера, может остаться неизмеренным** — тогда он невидим и принимает клики неверно; лечится `initialWidth`/`initialHeight` плюс `useUpdateNodeInternals()` при монтировании и смене размера. **Главное следствие:** пока `measured` нет хотя бы у одного узла, `nodesInitialized === false` и React Flow не рисует вообще ни одной связи (`edges` в сторе есть, `<g class="react-flow__edge">` в DOM нет, а маркеры есть). Поэтому `toFlowNode` сразу заполняет `measured: { width, height }`.

**Позиция мини-тулбара связи** — не считаем середину по координатам узлов: берём `path.getPointAtLength(length / 2)`, переводим через `path.getScreenCTM()` и вычитаем `rect` холста. Так тулбар садится на настоящую кривую при любом типе ребра и зуме.

**Свободное рисование** — оверлей `<svg>` с `transform` из `useViewport()`; точки получаем через `screenToFlowPosition`. Пока инструмент активен, React Flow отключает pan/zoom/выделение, а прозрачный слой перехватывает указатель; в базу пишем только завершённый штрих.

**Превью шаблонов** собираются из div'ов и процентов высоты: контейнер ряда должен быть `flex-1`, иначе `height: %` внутри auto-высоты схлопывается в полоску.

**Событие `change` для React** нужно отправлять с `bubbles: true`: слушатели React живут на корне, и событие без всплытия до них не дойдёт (в отличие от `input.onchange`).

**`db.transaction('rw', …)`** принимает не больше пяти таблиц поимённо — для всей базы передаём массив `db.tables`.

**Нативный `confirm()`** блокирует отрисовку окна: пока диалог открыт, страница не отвечает. В шаге полировки заменить на свои диалоги.
